## 1. 结论

**不要移除，改成"本地存为主、xapp 直插可选"。**

三条理由：

1. **架构是好的，错的只是后端选型。** 现在这个功能的失败点唯一一处：把内容写进了别人机器上不存在的 PostgreSQL。换成 SQLite 不动任何接口（`IQuickNoteDatabaseService.SaveAsync(content, source)` 签名不变），改动集中在一个类。
2. **它是这个 app 里唯一"用户主动创造内容"的模块。** 另外四个（鼠标/键盘/电脑时长/软件时长）都是"看统计"。速记是"用工具"。开源项目的留存靠后者，不靠前者。
3. **改造成本小，而且有现成范例。** SQLite 在这个仓库里是主流而不是新东西——`ClickDatabaseService` / `KeyDatabaseService` / `ProcessUsageTracker` 三处都是同一套路（建表 + 写入 + 查询），照抄即可。

但**去留决定之前，有一件事比它更急**（第 2 节）。

## 2. 先修这个：对没有 xapp 的用户，现在是"看着能用、一保存就失败"

README 第 71 行写的是：

【原文】未配置时该功能禁用，不影响其它功能。

【实际】不是禁用。链路是这样的：

| 步骤 | 实际行为 | 证据 |
|---|---|---|
| 1. 按下 `Win+Numpad0` | 热键**无条件注册**，照样响应 | `App.xaml.cs:117-121` 直接 `_globalHotkey.Start()`，没有任何前置判断 |
| 2. 速记窗弹出 | 正常弹出，还能抓前台窗口标题作来源 | `QuickNoteCaptureService.InvokeCapture()` 无配置检查 |
| 3. 打字 | 正常，看着一切可用 | — |
| 4. `Ctrl+Enter` 保存 | **永远失败**，报"速记保存失败"，内容保留让你重试 | `QuickNoteDatabaseService.cs:34-42`：没有连接串就记 Error 并 `return false` |

另外两处：

- 托盘菜单**无条件**有"打开速记窗""速记列表"两项（`App.xaml.cs:147-148`）。
- "速记列表"打开 `http://localhost:9009/quick-note`（`QuickNoteCaptureService.cs:43-50`）。用户本机 9009 端口如果跑着别的服务，会开出一个**无关页面**。

后果有两条比"功能坏掉"更糟：

- **它替用户占了一个全局热键。** 用户没打算用这个功能，却永久丢了 `Win+Numpad0`。
- **代码里硬编码了作者本机路径**：`DefaultEnvPath = @"C:\xapp-2026-06-30\.env"`（`QuickNoteDatabaseService.cs:18`）。这对任何别人都无意义，同时把你的本地目录结构带进了公开仓库。

**这不是"可选功能"，是"默认坏掉的功能"。** 对开源发布来说，这个比"要不要深入做"更该先处理。

## 4. 三个选项对比

| | A. 从开源版移除 | **B. 本地优先化（建议）** | C. 保留现状但"真禁用" |
|---|---|---|---|
| 做法 | 删 833 行 + Npgsql + 4 处文档 | 后端换 SQLite，列表变本地窗口；xapp 直插降级为可选后端 | 未配置时不注册热键、不显示托盘项、不出现入口 |
| 新增代码 | 0（净删） | ≈200–400 行 | ≈30 行 |
| 开源用户能不能用 | 不能（没有此功能） | **能** | 不能（但至少不碍事） |
| 丢掉什么 | 一个已打磨好的功能（单实例复用、多屏 DPI 定位、来源抓取、Toast 确认） | 无（xapp 用户照旧可用） | 无 |
| 遗留问题 | 无 | 需要维护两套后端 | 功能等于不存在 |
| 主要风险 | 无法回滚（文档要重写） | 两套后端的分支要测 | 掩盖问题，迟早还得决定 |

**C 只是把"坏功能"变成"没功能"，没有解决任何问题**，但它作为 B 或 A 落地之前的**止血措施**是合适的——成本 30 行，立刻消除"抢热键"和"打开无关页面"两个实质影响。

## 5. 推荐方案 B 的改造范围

```
QuickNoteDatabaseService  ← 唯一需要大改的类
  ├─ SaveAsync(content, source)                    ← 接口签名不变
  ├─ 未配置 ConnectionString / .env → 写本地 SQLite
  │    （quick_notes.db，表 QuickNoteRecords，照抄 ClickDatabaseService 的写法）
  └─ 配置了 ConnectionString → 走 Npgsql 直插 xapp（保持现状）
```

配套：

| 项 | 做法 |
|---|---|
| 存储位置 | `%APPDATA%\XAssistant\quick_notes.db`，与另外三个库并列 |
| 表结构 | `QuickNoteRecords(Id, Content, Source, CreatedAt)`，时间戳用现有约定（ISO 8601 `"o"`） |
| 列表页 | 主窗新增一页（复用现有 `Navigate` 导航），或继续用独立小窗。**不要**再依赖 `localhost:9009` |
| "打开 xapp 列表" | 仅在配置了 `SpaBaseUrl` 时显示 |
| 后端判定 | 一次判定、缓存结果，不要每次保存都重读配置文件 |
| 迁移 | 无需迁移——本地库是新建的，原库不动（符合"只增不删"纪律，见 `数据层改造-安全方案.md`） |

不改的部分：全局热键、捕获窗（含单实例复用、多屏 DPI 定位、来源抓取）、Toast 确认、`QuickNoteViewModel` 的保存失败重试逻辑。

## 6. 无论选哪个都要先修的 4 条

1. **未配置就不注册全局热键**（否则白占用户一个热键）。
2. **未配置就不显示托盘那两项**。
3. **"速记列表"不再默认指向 localhost**——改成本地列表，或未配置时隐藏该入口。当前行为可能打开用户本机 9009 端口上的无关服务。
4. **删掉 `DefaultEnvPath = @"C:\xapp-2026-06-30\.env"`**（`QuickNoteDatabaseService.cs:18`）。自动读 `.env` 这个"开箱即用"的便利是给自己用的，对别人只会造成困惑。

同时把 README 第 71 行改成与实现一致的描述。

## 7. 一个别被误导的数字

`Npgsql.dll` 是 **1.41 MB**，占框架依赖（FDD）包体 **5.07 MB 的 27.8%** —— 看着像一个"移除能省四分之一体积"的好理由。

**但对你实际发布的自包含包，它只占约 0.8%**（176 MB 里 1.41 MB）。

所以：**别拿体积当理由决定这个功能的去留。** 保留 Npgsql 换来的是"能对接自己的 PostgreSQL"这个可选能力，值这 1.41 MB。真正该用体积理由决定的是"要不要自带 .NET 运行时"那件事（见 `ui-upgrade/可行性评估.md` 附录）。
