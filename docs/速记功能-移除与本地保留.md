## 1. 结论：分两步走

**先保底，再长期。**

- **保底（现在做，5 分钟）**：打 tag + 导出文件快照。保证这份代码永远取得回来，之后再删就没有风险了。
- **长期（在 UI 升级落地前做）**：把速记改成"私有目录 + 约定加载"。让本地版**只多一个 `Local/` 目录，对共用文件零改动** —— 这样以后主线怎么改（UI 升级会大改托盘菜单和 Toast）都不会和它冲突。

**不建议的做法**：开一个 `personal` 分支长期 merge。理由是接下来 UI 升级会重写托盘菜单、加设置页、重做 Toast 样式，而这些正是速记的挂载点。每改一次就要解一次冲突，长期成本比那 40 行加载钩子高。

## 2. 第一步 · 保底（5 分钟，先做这个再删）

两件事，都很快：

**① 打一个 tag**（永久锚点，任何时候都能取回）

```powershell
git tag archive/quicknote-2026-09-21
git push origin archive/quicknote-2026-09-21
```

以后想取回任意文件：

```powershell
git checkout archive/quicknote-2026-09-21 -- Services/QuickNote Views/QuickNoteWindow.xaml
```

**② 导出一份脱离 git 的快照**（防 tag 被误删、也方便改成私有模块）

```powershell
$dst = "D:\private\XAssistant-local\_snapshot"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
git archive --format=zip -o "$dst\quicknote.zip" HEAD -- `
  Services/QuickNote `
  Services/Interfaces/IQuickNoteDatabaseService.cs `
  ViewModels/QuickNoteViewModel.cs `
  Views/QuickNoteWindow.xaml Views/QuickNoteWindow.xaml.cs `

```

`D:\private\` 建议独立成一个**私有 git 仓库**（`git init`），这样这份代码本身也有版本历史，不会散落。

做完这两步，删就没有后顾之忧了。

## 3. 第二步 · 长期（让本地版能跟着主线演进）

### 机制：私有目录 + 约定加载

**开源版里留一个通用的加载钩子**（≈40 行，不含任何 xapp 信息，本身是个正常特性）：

```csharp
// Services/LocalModules.cs —— 开源版就有，通用
namespace XAssistant.Services;

// 本机私有模块的挂载点。找不到实现时静默跳过（开源版即为此状态）。
public interface ILocalModule
{
    void Register(IServiceCollection services);   // 容器构建前
    void Attach(IServiceProvider provider);       // 启动完成后
}

public static class LocalModules
{
    private static IEnumerable<ILocalModule> Discover() =>
        Assembly.GetExecutingAssembly()
            .GetTypes()
            .Where(t => t is { IsClass: true, IsAbstract: false }
                        && typeof(ILocalModule).IsAssignableFrom(t))
            .Select(t => (ILocalModule)Activator.CreateInstance(t)!);

    public static void RegisterAll(IServiceCollection services) { /* 逐个 Register */ }
    public static void AttachAll(IServiceProvider provider)     { /* 逐个 Attach   */ }
}
```

对共用代码的改动只有 **2 处调用 + 1 处事件**：

```csharp
// App.xaml.cs 里
LocalModules.RegisterAll(services);        // 容器构建前
...
LocalModules.AttachAll(provider);          // Start 之后

// App.xaml.cs 里加一个静态事件，让私有模块能往托盘插菜单项
public static event Action<ContextMenuStrip>? TrayMenuCreated;
```

**私人版 = 一个被 gitignore 的目录**：

```
Local/                                  ← 加进 .gitignore
  QuickNote/
    QuickNoteModule.cs                  ← 实现 ILocalModule，唯一的挂载入口
    QuickNoteDatabaseService.cs
    QuickNoteCaptureService.cs
    GlobalHotkeyService.cs
    QuickNoteHotKey.cs
    QuickNoteWindow.xaml / .xaml.cs
    QuickNoteViewModel.cs
    QuickNoteSettings.cs                ← 从 AppSettings 剥离出来的私有配置
```

主 csproj 加通配（`Local/` 不存在时整组条件为假、完全为空）：

```xml
<ItemGroup Condition="Exists('Local')">
  <Compile Remove="Local/**/*.cs" />
  <Compile Include="Local/**/*.cs" />
  <Page Remove="Local/**/*.xaml" />
  <Page Include="Local/**/*.xaml" />
</ItemGroup>
<PackageReference Include="Npgsql" Version="10.0.3" Condition="Exists('Local')" />
```

> **为什么要有 `Remove`**：SDK 的默认通配本来就是 `**/*.cs`，`Local/` 就在项目目录下（联结也算），
> 直接 `Include` 会让同一个文件进两次 → `NETSDK1022 重复项`。先 `Remove` 再 `Include` 才是确定的。
> Npgsql 改条件引用要等到第 4 步（主仓库里还留着 `QuickNoteDatabaseService` 时会编译不过）。

`QuickNoteModule` 就是把 `App.xaml.cs` 里原有的那几行搬进来：

```csharp
internal sealed class QuickNoteModule : ILocalModule
{
    public void Register(IServiceCollection services)
    {
        services.AddSingleton<IQuickNoteDatabaseService, QuickNoteDatabaseService>();
        services.AddSingleton<GlobalHotkeyService>();
        services.AddSingleton<QuickNoteCaptureService>();
    }

    public void Attach(IServiceProvider provider)
    {
        var capture = provider.GetRequiredService<QuickNoteCaptureService>();
        var hotkey  = provider.GetRequiredService<GlobalHotkeyService>();
        hotkey.HotKeyPressed += capture.InvokeCapture;
        hotkey.Start();
        App.TrayMenuCreated += menu =>
        {
            menu.Items.Insert(1, new ToolStripMenuItem("打开速记窗", null, (_, _) => capture.InvokeCapture()));
            menu.Items.Insert(2, new ToolStripMenuItem("速记列表", null, (_, _) => capture.OpenList()));
        };
    }
}
```

**配置也要独立**：私有模块自己读 `%APPDATA%\XAssistant\local.json`（自己 `JsonSerializer.Deserialize`），不再占用公开的 `appsettings.json`。这样开源版的配置里不会出现 `ConnectionString`、`DatabaseUrlEnvPath` 这些词。

### 好处

| | 私人分支长期 merge | 私有目录 + 约定加载 |
|---|---|---|
| 对共用文件的改动 | 6 处（DI / 字段 / 热键绑定 / 托盘 ×2 / AppSettings） | **2 处调用 + 1 处事件**，且与 UI 无关 |
| UI 升级时冲突 | 高（托盘菜单必被重写） | **0** |
| 私人代码在公开仓库里的痕迹 | 分支名、历史、ADR 全在 | `.gitignore` 里 1 行 + 40 行通用钩子 |
| 开源用户 clone 后 | 正常 | 正常（`Local/` 不存在，通配为空） |
| Npgsql 依赖 | 公开依赖列表里有 | 条件引用，开源构建不拉 |

### 日常怎么用

`Local/` 不进主仓库，用**目录联接**让它出现在主仓库根目录下（Windows 上 symlink 要管理员，junction 不用）：

```powershell
cmd /c mklink /J "D:\code\XAssistant\Local" "D:\private\XAssistant-local\Local"
```

于是在主仓库里改速记代码，变更直接落在私有仓库那份；主仓库的 `git status` 因为它被 gitignore 而保持干净。

## 6. 关于 git 历史：删当前版本 ≠ 从开源里消失

要讲清楚这一点，免得你以为删了就干净了：

- 删掉当前版本后，**历史里仍然有**。任何人 `git log --all --diff-filter=D --name-only` 都能找到 `Services/QuickNote/QuickNoteDatabaseService.cs`。
- 更要紧的是：**v1.0.0 的 release 包和源码 zip 已经发出去了**，那份收不回来。
- 历史里暴露的具体内容是：一个表名 `quick_notes`、一条 `INSERT INTO quick_notes (content, source)` 语句、一个本机路径 `C:\xapp-2026-06-30\.env`，以及 `CONTEXT.md` 里指向另一个仓库文档路径的两处引用。

**怎么选：**

| | 只删当前版本 | 重写历史（`git filter-repo` + 强推 + 重新发版） |
|---|---|---|
| 代价 | 无 | 所有 clone/fork 失效、release 版本号要重来、v1.0.0 仍能被别人手里的旧副本看到 |
| 效果 | 未来版本干净，历史仍可查 | 未来和历史都干净（但已经下载的副本管不了） |

**我倾向只删当前版本。** 历史里那点东西对陌生人的信息量是"这人还有个私有项目"，不构成风险；而重写历史的代价是实打实的。除非你特别在意 `xapp-2026-06-30` 这个目录名被看到，否则不值得。

## 7. 执行顺序

照这个顺序做，每步都可停：

1. **打 tag + 导出快照**（第 2 节）← 先做这个，之后才有底气删
2. **在开源版加通用加载钩子**（第 3 节的 40 行 + csproj 两条通配）并**验证开源版能正常编译运行**（`Local/` 不存在时应完全无感）
3. **把快照改造成 `Local/QuickNote/`**，用 junction 挂进主仓库，**验证本地速记功能照旧可用**（热键、来源抓取、写 xapp 库、Toast）
4. **删干净**（第 4 节清单），跑一遍开源版构建
5. **改文档**（CONTEXT.md 重写、CLAUDE.md、README、删 3 个 ADR）
6. **改 v4 原型 6 处**（第 5 节），再跑一次 `_verify/v4-check.mjs` 确认没有断言失败

第 2、3 步先于第 4 步，是这套方案的关键——先证明"拆开之后两边都能跑"，再删。
